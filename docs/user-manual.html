This manual walks through every card in Kamra Compressor OS with a ready-to-type sample dataset. Hub pages (S-1…S-7) open pre-filled with a tested sample — press Run and read. Workstream pages (W-01…W-06) use the KES Demo Plant: a ceramic-ware unit running two 75 kW oil-injected screw compressors (600 Nm³/hr each) at 7 bar g, 6,000 hrs/year, electricity at ₹5/kWh.

W-01

New System Design (Greenfield)

Workspace → System Planning

Design a factory compressed-air system from scratch: consumer register → design pressure → station capacity with standby philosophy → treatment → storage → energy.

Steps

  1. Add each air consumer with its flow, pressure and running pattern.
  2. Set system allowances (leakage, future expansion) and control margin.
  3. Choose the standby philosophy (N / N+1) and review station capacity.
  4. Enter tariff and hours to see the annual energy picture. Persist when done.

W-02

Existing Plant Assessment (Brownfield)

Workspace → Plant Assessment

The audit workhorse. Inventory the installed machines, log measured operating points, and get losses and improvement opportunities in ₹.

Steps

  1. Add each installed compressor (technology, control mode, rated FAD / pressure / motor kW).
  2. Log measured points per machine (state: loaded / unloaded / part-load, with flow, pressure, power).
  3. Enter system snapshot (total flow, header pressure, total power) and any measured leakage.
  4. Set tariff, annual hours and the optimized target pressure — read the opportunity list.

G-01

The audit trail. Anything you run with Persist This Analysis ticked becomes a calculation case with a code, title and notes — filterable by type (including Distribution Network), openable in detail, and feeding assessments and controlled reports.

Persistence habit

why you can defend every result

House rule: no engineering constant enters this platform without a citable standard or manufacturer-verified source. What you'll meet in results:

ReferenceWhere it acts
ISO 1217 (+Amd 1)Rotary screw acceptance basis & standard-air correction

FIX

Troubleshooting

the usual suspects
SymptomLikely cause → fix
"Login failed" with correct passwordFrontend pointing at the wrong backend port — check VITE_API_BASE_URL in frontend/.env matches the running backend (dev: http://localhost:8010/api/v1), restart npm run dev.
"Address already in use" on backend startAnother service holds the port (on the dev machine, 8000 = Bill Book). Identify with ss -tlnp | grep <port> and ls -l /proc/<pid>/cwd; run this backend on its own port.
Analysis returns HTTP 422 with a messageThat message is the engineering validation itself (e.g. a path referencing an unknown segment) — fix the input it names.
Result fine but nothing in Calculation RecordsPersist This Analysis wasn't ticked, or code/title left empty — both are required to save.
Can't find the way back from a hub pageUse the Advanced Engineering button (returns to the hub) or the browser Back button. A clearer back label is on the improvement list.
